# Изменения версии 2.0 — 6 ноября 2026

## Реализовано

- JSON по формату презентации: transcript, speaker_id, start_ms/end_ms в целых миллисекундах, text. Дополнительно TXT/SRT и общий ZIP всех диалогов с project.json.
- Множественный импорт: каждый MP3/другой файл получает отдельный UUID и сохраняет имя. Обработка файлов идёт через общую последовательную очередь.
- Запись разговора в foreground-сервисе, предварительная расшифровка во время записи и автоматическая финальная обработка после остановки. Запись переживает сворачивание Activity. После убийства процесса сохранённый фрагмент восстанавливается при запуске.
- Локальная Pyannote segmentation INT8 для акустических границ и возможных наложений голосов. Основной encoder WeSpeaker; экспериментальный Whisper pooling сохранён. Неуверенная речь остаётся неизвестной.
- Реальная локальная LLM Qwen2.5 0.5B GGUF через llama.cpp для пунктуации. Проверка запрещает изменение последовательности слов и чисел; при нарушении остаётся исходный текст.
- Глобальные UUID людей и отдельные локальные ID говорящих. Возможное совпадение между диалогами предлагается подтвердить; после подтверждения доступны общее имя и переходы в другие диалоги. Повторное использование номера кластера само по себе не означает того же человека.
- Предыдущие версии текста и отмена правок. Атомарные контрольные точки ASR/эмбеддингов для повторного запуска. Миграция Room v1 → v2.
- Пакет всех моделей с проверкой SHA-256 и установкой через системный файловый диалог без интернета на телефоне.

## Исправлено

- Падение при нулевом суммарном центроиде разнонаправленных эмбеддингов.
- Неверное акустическое сходство, взятое из первой реплики человека вместо пересекающегося интервала; объединение сходства теперь учитывает длительность.
- Недостижимая ветка повторного определения известного голоса по кластеру: строгая проверка центроида дополнена более мягким согласованием отдельных окон.
- Остановка аудио при прокрутке: плеер вынесен из LazyColumn.
- Избыточная память HDBSCAN: треугольная матрица и обход без глубокой рекурсии. Зафиксирована политика одинаковых расстояний и добавлены независимые эталоны.
- Одновременное удержание тяжёлых моделей в стандартном pipeline: Whisper освобождается до диаризации, LLM загружается после акустических моделей.
- Количество потоков ограничено ядрами; нативный код оптимизирован и в debug APK. В x86_64 включён базовый SSE4.2.
- Ошибка JNI callback модели сегментации с современными Kotlin-лямбдами: используется явный класс с требуемой сигнатурой.
- Сведения об удалённом профиле убираются из глобальных связей и сохранённых версий; оригинальное аудио разговоров сохраняется.
- Буферизация декодированного PCM заменяет отдельную запись каждого сэмпла. Ошибки частичного импорта отображаются в итоговом сообщении.

## Следующие улучшения по приоритету

1. Размеченный русскоязычный набор: WER, DER/JER, погрешность границ, FAR/FRR. Калибровать пороги отдельно на независимых голосах и микрофонах. Это основной следующий шаг для точности.
2. Проверка и ускорение на целевом ARM64-телефоне: квантование Whisper, аппаратные backend после измерения, адаптивная частота черновика. На эмуляторе полная обработка пока медленнее реального времени.
3. Подавление шума отдельной моделью с сравнением WER до/после. VAD сейчас определяет речь, но не классифицирует каждый вид фонового звука.
4. Локальное forced alignment для уточнения времени слов. Текущие миллисекунды в JSON — единицы измерения, а не гарантия миллисекундной точности.
5. Разделение одновременных голосов. Сейчас есть отметка возможного overlap, но смесь не превращается в две независимые расшифровки.
6. Улучшение голосовых профилей по подтверждённым фрагментам из разных условий; оценка устойчивости на коротких ответах и похожих голосах.

Инженерные источники: [Sherpa speaker diarization](https://k2-fsa.github.io/sherpa/onnx/speaker-diarization/index.html), [Whisper](https://github.com/ggml-org/whisper.cpp/tree/v1.8.2), [Qwen2.5 GGUF](https://huggingface.co/Qwen/Qwen2.5-0.5B-Instruct-GGUF), [llama.cpp](https://github.com/ggml-org/llama.cpp/tree/b6800), [HDBSCAN reference implementation](https://github.com/scikit-learn/scikit-learn/tree/main/sklearn/cluster/_hdbscan). Более ранний обзор вариантов сохранён в отдельной папке аудита. Идеи из источников адаптированы к требованию локальной обработки; наличие похожей функции в другом продукте не доказывает её качество в нашем приложении.
