# LocalVoices 6.0 — краткие ответы по решению

## 1. Что делает приложение?

Приложение локально превращает разговор в структурированную расшифровку. Оно показывает текст реплик, определяет говорящих, сохраняет временные метки и экспортирует результат в JSON, TXT или SRT.

## 2. Как им пользоваться?

Есть два сценария:

- **Импорт MP3:** выбрать файл → дождаться декодирования → нажать «Распознать» → открыть результат → экспортировать JSON.
- **Диктофон:** нажать «Записать разговор» → говорить → остановить запись → приложение автоматически сохранит аудио и запустит обработку.

Для основного сценария предпочтительна запись внутри приложения: анализ начинается ещё во время разговора.

## 3. Как устроена архитектура?

`микрофон/MP3 → PCM 16 кГц mono → определение речи → распознавание → голосовые embeddings → кластеризация говорящих → временные метки → сохранение → экспорт`

В режиме диктофона приложение обрабатывает короткие накопившиеся фрагменты, сохраняет промежуточные результаты и после остановки выполняет финальную сверку всего диалога.

## 4. Какие модели и модули используются?

- **GigaAM-v3 E2E CTC** — распознаёт русскую речь.
- **Silero VAD** — отличает речь от пауз и неречевого сигнала.
- **Speaker segmentation** — уточняет акустические границы речевых участков.
- **WeSpeaker encoder** — превращает голосовые окна в embeddings.
- **HDBSCAN** — группирует embeddings по говорящим без заранее заданного числа людей.
- **Qwen2.5-0.5B через llama.cpp** — локально восстанавливает пунктуацию и не меняет последовательность распознанных слов.
- **MediaCodec** — декодирует MP3 и приводит его к PCM 16 кГц mono.
- **Room/WorkManager** — сохраняют записи и ведут очередь обработки.

## 5. Почему приложение быстрее работает с диктофоном?

При записи embeddings, VAD и черновой текст считаются по ходу разговора. Эти результаты попадают в live-кэш и переиспользуются после остановки.

При импорте MP3 сначала нужно полностью декодировать файл и создать внутренний WAV. Только после этого начинается основной анализ. Поэтому время декодирования MP3 нужно считать отдельно от времени ASR и диаризации.

## 6. Какой результат выдаёт приложение?

Основной формат проверки — JSON:

```json
{
  "transcript": [
    {
      "speaker_id": "speaker_1",
      "start_ms": 1250,
      "end_ms": 4380,
      "text": "Добрый день!"
    }
  ]
}
```

Время указано в миллисекундах от начала аудио.

## 7. Работает ли приложение без интернета?

Да. Все модели встроены в APK, аудио не отправляется на сервер, облачные API для распознавания и диаризации не используются.

## 8. Какие ограничения есть?

Ошибки чаще возникают при сильном шуме, перекрывающейся речи, очень коротких репликах и похожих голосах. Большие файлы лучше разделять. Точность и скорость зависят от устройства.

Короткий MP3 подходит для проверки импорта и отсутствия падения, но не полностью показывает преимущество потоковой обработки длинного разговора.

## 9. Что показали собственные тесты?

Распознавание текста в большинстве проверок было стабильным. Основные ошибки были связаны с диаризацией. В медленной конфигурации импортированный файл обрабатывался примерно за 1,5 длительности аудио; при записи внутри приложения часть работы выполняется заранее.

Проверены импорт MP3, обработка, экспорт JSON и повторный запуск приложения без падения.

## 10. Что нужно установить проверяющему?

Нужно установить APK из GitHub Release, разрешить доступ к аудио и микрофону, импортировать MP3 или сделать запись через диктофон, нажать «Распознать» и проверить расшифровку и экспорт JSON.
